1. How to Properly Initialize Preventive Maintenance of an Equipment

Follow this mandatory end-to-end initialization workflow to properly calibrate equipment baseline meters and configure customized PM schedules before logging daily operations:

1.1
1.1 Go to Equipment Registry & Operations
Navigate to App Registry > Equipment Registry & Operations (route: /global-settings/vehicle-registry). This is your central command center for fleet asset onboarding, baseline odometer configuration, and PM schedule calibration.
1.2
1.2 Search to Edit or Add Equipment
Depending on your asset onboarding status:
  • To Edit Existing Equipment: Use the search filter bar to find the target Plate Number / Unit ID, then click the Edit button () in the table actions.
  • To Register New Equipment: Click the "+ Add Equipment" button to open the asset enrollment form. Fill in the Plate Number, Conduction Sticker Number, Make, Model, and assign the appropriate Service Standard (e.g. STD-HEAVY).
1.3
1.3 Input Initial Service Reading and Save
In the Service Reading field, input the starting meter reading (e.g. Engine Runtime Operating Hours for heavy machinery, loaders, and prime movers, or Odometer Kilometers for highway haulers). Toggle Active Status to Active and click Save.
1.4
1.4 If Odometer Did Not Start at 0 (Not Brand New) → Update PM Schedule
If the equipment did not start at 0 (i.e. existing asset with prior operating history):
  1. Click on the equipment in the master table to select it.
  2. Switch to the "Equipment PM Status" tab at the top.
  3. Click the blue "Update PM Schedule" button ().
  4. Input the customized PM schedule values based on your physical maintenance logs:
    • Previous Reading: Reading when that PM tier was physically executed last.
    • Date Completed: Historical completion date of that service.
    • Current Target Reading: Exact meter threshold when the next tier is due.
    • Next Target Reading: Subsequent service threshold.
  5. Click Save to store the customized schedule.
💡 Note: If the equipment is brand new starting at 0, standard interval increments (e.g. 250h / 5,000km steps) apply automatically without needing historical calibration.
1.5
1.5 You Can Now Start Using Daily Inspection & Telemetry
Your equipment's preventive maintenance engine is now fully initialized and synchronized! You can now start using Daily Inspection & Telemetry (route: /daily-inspection) to capture daily end-of-shift readings, track automatic PM intervals, and flag defects.

Operational Prerequisite
Before logging daily shift telemetry for a newly acquired or newly registered asset, ensure it has been properly initialized via How to Properly Initialize Preventive Maintenance of an Equipment (Steps 1.1–1.5).
Primary Roles Yard Inspector, Shift Driver, Shop Clerk
Source Navigation Maintenance Plan > Daily Inspection
Primary Database Tables vehicle_daily_logs, log_risks
System Trigger Recalculates PM Due Thresholds & Updates Master Reading

Select Equipment via Vehicle Picker

Stage 3: Preventative Control

Equipment PM Details & One-Click Completion

Tracks PM tiers (PM2 through PM7). When accumulated service readings exceed target thresholds, red alert flags highlight the due service. Shop supervisors execute one-click completion upon physical service sign-off.

Primary Roles Maintenance Supervisor, Shop Foreman
Source Navigation Maintenance Plan > Equipment PM Details
Database Stored Procedure rpc('completed_vehicle_pm', { p_pm_level, p_vehicle_id })
Transaction Output Advances Target Counter, Records Completed Timestamp, Clears Flag
RC-MRO — /vehicles
Figure 3.1: Equipment PM Details screen showing fleet list, current service readings, and PM schedule breakdown. Click to expand
1
Open Equipment PM Details Modal
Search by plate number and click View Details to open the PM Schedule Breakdown.
2
Review PM Schedule Grid
Examine the row for each tier (PM2 to PM7). If Current Reading >= Current PM Target, the row turns red and displays an active green Completed button.
3
Execute Completion Procedure
When physical maintenance is verified, click the Completed button. RC-MRO invokes the completed_vehicle_pm RPC procedure:
  • Sets pmX_previous = current_service_rdg
  • Records pmX_datecompleted = NOW()
  • Advances pmX_current = pmX_next
  • Recalculates pmX_next = pmX_current + standard_interval
  • Clears the overdue red flag immediately.

Primary Roles Component Rebuild Specialist, Workshop Supervisor
Source Navigation Maintenance Plan > Component History
Primary Database Tables equipment_components, equipment_component_history
Transaction Output Net component run-hours, scrap audit status (is_scrapped)
RC-MRO — /component-history
Figure 6.1: Component History screen showing serialized units, vehicle installations, accumulated mileage, and scrap status. Click to expand
1
Teardown & Component Removal
When an assembly fails or is scheduled for overhaul, locate the unit in Component History and click Remove Component. Record the vehicle reading at removal and teardown notes. RC-MRO computes the net running hours accumulated on that asset.
2

If structural casing cracks or catastrophic damage prevents rebuild, flag the component as is_scrapped = TRUE. This prevents the unit from ever being remounted on any vehicle.

Stage 7: Reliability & Safety

Incident Investigation & 4-Pillar Root Cause Analysis

Closes the reliability loop when field breakdowns or safety incidents occur. Captures financial loss estimates and systematically breaks down causes across Conditions, Acts, Personal Factors, and Work-Related Causes.

Primary Roles Safety Officer, Reliability Engineer, Quality Auditor
Source Navigation Incident Mgmt > Incident Report
Taxonomy Framework 4-Pillar RCA (Conditions, Acts, Factors, Causes) + FMEA RPN
Transaction Output Corrective Actions, Incident Loss Tracking, Preventive Rule Adjustments
RC-MRO — /incident-management/incident-report
Figure 7.1: Incident Report management screen showing incident master records, severity badges, and 4-pillar RCA tabs. Click to expand
1
Log Incident Master Record
Record Incident Reference Number, Vehicle ID, Incident Date/Time, Severity (Low, Medium, High, Critical), Reported By, and Estimated Financial Loss.
2
Conduct 4-Pillar Root Cause Analysis
Select the incident and populate findings across all 4 analysis pillars:
  1. Substandard Conditions: Mechanical failure (e.g., brake line puncture, fatigue crack).
  2. Substandard Acts: Operator behavior (e.g., driving with low air pressure warning).
  3. Personal Factors: Human factors (e.g., operator fatigue, inadequate shift handover).
  4. Work-Related Causes: Systemic causes (e.g., inadequate PM inspection checklist interval).
3
Close Loop with Preventive Actions
Use RCA findings to update PM intervals in Service Standards or adjust FMEA detection protocols in App Settings to ensure permanent mitigation.
Operationalizing FMEA — End-to-End Setup & Daily Use

Before FMEA risk flags can be used in daily inspections, System Administrators must configure the RCA taxonomy, validate FMEA settings, and populate the Master FMEA list. Follow these three sequential phases:

1
Phase 1: Fill-Up Root Cause Analysis (RCA) Settings
Navigate to /settings/rca. Populate the four taxonomy pillars used to classify all incident causes:
  • 1.1 Unsafe Conditions — Physical or environmental hazards (e.g., wet floor, defective equipment part, poor lighting).
  • 1.1 Unsafe Acts — Operator behavior deviations (e.g., operating without PPE, bypassing safety checklist).
  • 1.1 Personal Factors — Human-side causes (e.g., fatigue, inadequate training, health limitations).
  • 1.1 Work-Related Causes — Systemic root causes (e.g., inadequate PM schedule, missing standard operating procedure).
💡 These four pillars map directly to the 4-Pillar RCA framework used in Incident Reports.
2
Phase 2: Fill-Up and Validate FMEA Settings
Navigate to /settings/fmea. Complete the following three sub-tasks:
  1. 2.1 – Review and Validate RPN Values: RPN (Risk Priority Number) is calculated as Severity × Occurrence × Detection. Review each FMEA entry's RPN score. Flag any entries with high RPN values for immediate corrective action priority.
    RPN = Severity × Occurrence × Detection
  2. 2.2 – Populate FMEA Constants (Control and Effects): Define the detection control methods and failure effects for each failure mode. Controls describe how the failure is currently being detected (e.g., visual inspection, scheduled monitoring). Effects describe what happens to the system when the failure occurs (e.g., loss of braking, engine shutdown).
  3. 2.3 – Populate Master FMEA (Unsafe Conditions, Unsafe Acts, Personal Factors and Work-Related Causes): Map each FMEA failure mode to one of the four RCA taxonomy categories established in Phase 1. This creates the selectable Master FMEA List that operators will use when tagging daily inspection flags.
3
Phase 3: Operationalize FMEA in Daily Inspection & Telemetry
With RCA taxonomy and Master FMEA populated, inspectors can now link field observations directly to FMEA risk codes during daily operations:
  1. 3.1 – Inspect the Equipment and Input Daily Inspection Form and Save: Navigate to /daily-inspection. Select the equipment via the Vehicle Picker, enter the current service reading, record remarks on any observed defects or anomalies, and click Submit Daily Log.
  2. 3.2 – Move to Inspection Flags, Search for the Equipment/Vehicle and Select Flags: Switch to the Inspection Flags tab. Search for the equipment by plate number or unit ID. Select one or more flags from the Master FMEA List — flags are pre-classified into Unsafe Conditions, Unsafe Acts, Personal Factors, and Work-Related Causes. Save the flag to formally record the risk against the inspection entry.
    ⚠️ Note: Flags are sourced exclusively from the Master FMEA List. Ensure Phases 1 and 2 are completed and the Master FMEA is populated before using Inspection Flags in daily operations.
